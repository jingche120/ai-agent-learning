# card — 對話轉卡片盒筆記

> 使用本 skill 時，先明確告訴使用者：「我用 card skill 來做卡片」。

## 跟 new-note 的分工（不要搞混）

| | 這個 skill（card） | [new-note](../new-note/SKILL.md) |
|---|---|---|
| 輸入 | 已經發生的對話 | 一個要寫成文件的主題 |
| 產物 | N 張原子卡，一張一個概念 | 一篇長文，編號章節＋結尾檢查清單 |
| 存到哪 | Heptabase Inbox（或貼給使用者自己貼） | 這個 repo 的 `.md` 檔 |

**判準**：內容的價值來自「順序」→ 用 new-note；價值來自「概念本身、之後可以跟別的概念連起來」→ 用本 skill。像「開新專案的七個步驟」這種東西**不要**拆成卡片，順序就是它的全部價值。

## 卡片規則（必守）

### 1. 原子化：一張卡只講一個概念

不要把多個重點塞進同一張。自我檢查，出現下面任一種就該拆：

- 標題裡出現「和」「以及」「與……的差異」串起兩個主張
- 內文出現第二個「因為」——通常代表在解釋第二件事
- 這張卡可以獨立被別的卡引用嗎？如果引用它的人只想要其中一半，就是不夠原子

### 2. 用使用者自己的話重寫

**不要照抄對話原句**。卡片盒的重點是「重寫過才算內化」，貼原文等於沒讀。用使用者在對話中的用詞習慣與立場來寫，不要換成教科書腔。

### 3. 標題是完整主張，不是主題名詞

| ❌ 名詞 | ✅ 完整想法 |
|---|---|
| 「skill 的作用範圍」 | 「skill 屬於專案，不屬於你 —— 綁著檔案路徑的 skill 換專案就會壞掉」 |
| 「CLAUDE.md 與記憶」 | 「CLAUDE.md 是你維護的使用說明書，不是 AI 自己寫的筆記」 |

標題要能單獨讀懂，因為未來你在 Heptabase 看到的通常只有標題。

### 4. 連結不准捏造

「連結」欄位優先指向**真的存在**的東西：`card/` 裡的既有卡、這個 repo 的筆記、`skill範例/` 底下的檔案、或這次同批產出的其他卡。

**動手前先 `ls card/`**，看看已經有哪些卡可以連 —— 這是卡片盒能長出網絡的關鍵，跳過這步就只是在生一堆孤島。

不確定使用者的 Heptabase 裡有沒有某張卡時，寫成 `→ (待確認是否已有此卡)〈卡名〉`，**不要**假裝知道它存在。這條跟 [paper-card 範例](../../../skill範例/paper-card.md)「問不到就標（缺），不要捏造」是同一個原則。

### 5. 不為了湊數量產卡

一段對話可能只值 2 張卡。寧可少而紮實，也不要把過場的閒聊、已經是常識的東西各生一張。產出前先問自己：這張卡三個月後還有人會想連到它嗎？

### 6. 對話裡講過 ≠ 查證過

卡片內容若包含**客觀事實**（某功能怎麼運作、某設定叫什麼名字），照 [CLAUDE.md](../../../CLAUDE.md)「寫入前先查證」處理。

不能因為「這是我們剛剛討論過的」就跳過 —— 對話裡我可能講錯，而卡片會把那個錯誤固化下來、匯進 Heptabase、再跟其他卡連起來。**錯的卡比錯的長文難清理得多。**

## 卡片格式

每張卡照這個結構：

```markdown
# <標題：一句話點出核心主張，不是主題名詞>

<內文：2-4 句解釋這個概念。用使用者自己的話，說清楚「這是什麼」與「為什麼成立」。>

**連結**
→ [〈另一張卡的標題〉](./〈檔名〉.md)
→ [〈repo 既有筆記〉](../〈路徑〉.md)

**標籤**：#關鍵字1 #關鍵字2

**來源**：<哪次對話／哪份資料，寫得夠具體讓未來的你找得回來，含日期>
```

草稿階段貼在對話裡時，卡與卡之間用 `---` 分隔線隔開，方便逐張檢視。

## 存檔規則

卡片存進 **`card/`**（repo 根目錄底下），**一張卡一個檔**。

不要把一批卡塞進同一個檔 —— 卡片盒的雙向連結靠「一卡一檔」才成立，塞成一份就退化回普通筆記了。

| 項目 | 規則 |
|---|---|
| 檔名 | **簡短中文主題**，如 `skill屬於專案.md`。不加日期（日期寫在「來源」欄，加了連結會很難寫） |
| 完整標題 | 寫在檔案第一行的 `#`，檔名只是短代號 |
| 連結語法 | markdown 相對連結 `[標題](./檔名.md)`，在 VS Code 可直接點開 |
| 目錄不存在 | 直接建，不用問 |
| 檔名撞名 | **先問使用者**是要更新舊卡還是換個檔名，不要直接覆蓋 |

> `card/` 已加進 `.gitignore`，**不進版控** —— 它是匯進 Heptabase 前的暫存區。這是刻意的：避免 repo 與 Heptabase 兩份互相競爭、還要自己管同步。也因為不進版控，**覆蓋掉的卡片救不回來**，所以撞名一定要問。

## 流程

1. **先掃過這段對話**，挑出真正值得留的概念。
2. **`ls card/`** 看既有卡片，找可以連結的對象。
3. **產出卡片草稿**貼在對話裡，用 `---` 分隔，方便逐張檢視。
4. 寫完回報：建了哪幾個檔、哪些卡互相連到了。

> 提計畫、等使用者同意、草稿確認後才寫檔 —— 照 [CLAUDE.md](../../../CLAUDE.md)「操作前先對齊」走，本檔不重複。提計畫時要講明：**打算做幾張、各自主題、檔名**，數量或取捨有疑慮就在那時問。

## 之後匯進 Heptabase

目前**還沒有設定 Heptabase MCP**（`~/.claude.json` 的 `mcpServers` 是空的，工具清單裡沒有 `save_to_note_card`），所以流程停在寫進 `card/`。

- **不要**嘗試呼叫 `save_to_note_card`，也不要假裝存好了。
- 使用者自己把 `card/` 的檔案匯進 Heptabase 時，**連結語法要從 `[標題](./檔名.md)` 轉成 Heptabase 的 `[[標題]]`**。有需要就幫他轉一份。
- 之後若 `save_to_note_card` 真的可用：寫完 `card/` 後**問使用者**要不要同步進 Inbox，同意才呼叫。往這個 repo 以外的地方寫東西，一律先問。
