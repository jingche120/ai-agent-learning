# AI 應用專案諮詢師｜互動學習課綱

> 核心目標：先讓我真正學會、能獨立實作與除錯；完成核心能力驗收後，才開始練習教學與顧問溝通。  
> 使用方式：由 Codex 與 Claude Code 共用本課綱、進度與驗收標準，在同一個 Git 專案中逐步學習。  
> 現有基礎：Python、JavaScript、n8n、自動化、本地 LLM、API、Notion，以及 RAG 串接本地端 API。

---

## 一、完成這套課程後，我要能做到什麼

### 技術能力

1. 獨立說明並設計 Agent 架構。
2. 分辨 Tool、Workflow、Agent、Skill 與多 Agent。
3. 建立、測試與除錯包含 `SKILL.md` 的 Agent Skill。
4. 理解並實作漸進式載入與技能資料夾設計。
5. 獨立完成 Git branch／commit／PR／review／merge。
6. 設計、評估與改良 prompt，而非只憑感覺判斷回答。
7. 說明並診斷自己做過的 RAG＋本地 API 架構。
8. 判斷什麼情況適合多 Agent、RAG 或固定 Workflow。
9. 辨識資料安全、權限、幻覺與自動化風險。
10. 能在 macOS 與 Windows 情境中協助基本環境問題。

### 整合實戰

1. 把一個既有專案抽象成可重複使用的 Agent Skill。
2. 使用完整 Git／GitHub 流程開發。
3. 建立正例、反例與故障測試。
4. 留下架構決策、失敗分析與驗收證據。
5. 在沒有逐步答案的情況下完成綜合任務。

### 教學與求職能力

只有完成技術與整合實戰後，才進入這一部分：

1. 把已經學會的技術翻譯成非工程語言。
2. 使用提問協助他人理解與除錯。
3. 製作教學文件、SOP 與會談紀錄。
4. 把實作證據轉成履歷與面試故事。

## 二、能力等級與通過規則

| 等級 | 意義 | 判定方式 |
|---|---|---|
| L0 | 未接觸 | 不知道核心概念或用途 |
| L1 | 能理解 | 看過說明後能回答基本問題 |
| L2 | 能操作 | 有提示時能完成任務 |
| L3 | 能獨立 | 無逐步答案仍能完成、驗證與基本除錯 |
| L4 | 能教人 | 能診斷他人卡點，並讓對方自己完成 |

### 本課程的關卡

- 技術必備課程必須達到 **L3**。
- 完成核心技術與整合專案前，不要求 L4。
- 教學階段開始後，指定項目才要求 **L4**。
- 「看懂了」、「AI 幫我做完了」或「曾經用過」不能單獨作為通過證據。
- 已有經驗的項目可以直接接受診斷測驗；通過就跳過基礎教學。

### 每一堂技術課的固定流程

1. **先備診斷**：確認已知與未知。
2. **必要觀念**：只補目前需要的內容。
3. **引導練習**：提供提示，但不直接完成。
4. **獨立實作**：在沒有逐步答案下完成任務。
5. **變化題**：換一個情境，確認能轉用。
6. **故障題**：根據證據定位問題。
7. **驗收與紀錄**：保存產出並更新能力等級。

此階段可以要求我「說明判斷理由」，但不要求我設計教學或教會別人。

## 三、雙 AI 共用規則

### 共用事實來源

正式專案建立後，兩個 AI 都以以下檔案為準：

- `docs/LEARNING_PLAN.md`：本課綱。
- `docs/PROGRESS.md`：目前能力與課程進度。
- `docs/EVALUATION_RUBRIC.md`：共同驗收標準。
- `docs/DECISIONS.md`：重要選擇與原因。

### 協作規則

1. 開始前先讀進度，再讀本次課程。
2. 一次只進行一個主要學習任務。
3. 一個 AI 擔任導師時，另一個 AI 可以擔任獨立驗收者。
4. 驗收者必須檢查原始產出，不可只接受另一個 AI 的結論。
5. 同一時間只由一方修改 `PROGRESS.md`。
6. 不可因更換 AI 而擅自跳課或降低標準。
7. 若兩個 AI 判斷不同，記錄於 `DECISIONS.md`，比較雙方依據後再決定。
8. 學習者本人必須理解並確認重要修改。

## 3-2 學習者診斷

先判斷對方缺少概念、操作、證據、除錯方法或信心，再選擇教法。

## 3-3 提問引導式教學

練習在「直接給答案」與「只問問題不提供幫助」之間提供適量支架。

## 3-4 即時除錯引導

使用：

1. 預期發生什麼？
2. 實際發生什麼？
3. 有哪些證據？
4. 哪些假設可以先驗證？
5. 如何確認修改有效？

## 3-5 教學文件與 SOP

建立適用對象、先備條件、操作步驟、檢查點、常見錯誤、安全提醒與驗收方式。

## 3-6 模擬教學

由另一個 AI 或真實對象扮演非工程學習者，進行完整教學。

## 3-7 回饋修正

保存學習者卡點、原教法、回饋、修改與再次驗證。

### L4 通過標準

- [ ] 能判斷學習者真正卡點。
- [ ] 能調整提示程度。
- [ ] 學習者最終能自己完成。
- [ ] 教學文件能由陌生人操作。
- [ ] 有回饋與修訂證據。
